# 實測證據與界線

Customized by Platyun

> **歷史基線**：這是 2026-11-15 第一版整理稿（[8c3651f](https://github.com/Platyun/ios-location-research/tree/8c3651f6c719876d15dfb9274e5840f6a57a48fd)），保留供追溯。現行內容以[整合總結](cross-repo-summary.md)為準。2026-11-15 更正兩處事實：研究起點是 itool-fix 的早期距離限制研究；iOS 27.2.1 是同一台手機在 27.0.1 實測通過後更新系統再做的複測。

## 使用者實測回報

### 早期對照與現象

- 同一定位配件在舊系統可遠距離選點，新系統曾出現約 20 km 附近失敗，以及約 30 秒回跳。
- 早期開關 VPN、變更放行／拒絕及系統繞過設定，沒有改善當時問題。
- 後續在套用阻斷配置並重開機後，曾成功於多個相距較遠的目標地點間切換。實際地點已概括化，不公布個人位置或移動軌跡。
- 曾有效的組合流程是：設定配置、重開手機、關閉定位、啟用 VPN 並連接配件、選點、開啟定位。這是整體流程的回報，沒有獨立隔離配置與重開機的效果。
- 後續核心問題轉為失效後如何免整機重開重新套用；不再限定單一配件型號。

### 2026-11-14：iOS 27.0.1

使用者提供的探測匯出紀錄顯示：系統為 iOS 27.0.1，runtime 可找到 CLLocationManager 的 shutdownDaemon 類別方法，回傳型別為 B、大小為 1；一次手動呼叫正常返回 YES，原始值為 1。

收到不重按、不重開、依原流程重新套用的指示後，使用者回覆成功。當時沒有完整記下呼叫前是否確處於失效狀態、全部中間操作或對照組，不能補寫成嚴格受控試驗。

研究裝置後續補充為 iPhone 16 Pro；原始匯出紀錄本身沒有機型欄位。

### 2026-11-15：iOS 27.2.1

使用者在 iOS 27.0.1 實測通過後，把同一台 iPhone 16 Pro 更新到 iOS 27.2.1 再複測，回報成功，並明確補充沒有重開整機。這是對免整機重開目標的直接使用者回報，也是同一測試在系統更新後的複測。

本次未提供新的 runtime 匯出紀錄、呼叫回傳值或詳細操作順序，不能沿用舊版 YES 作為新版呼叫輸出。使用者表示維持多久不是本次重點，因此不將持續時間設為此目標的驗收條件。

## 建置紀錄

原研究交接記錄 Xcode 27.2、iOS 27.2 SDK 的未簽名建置成功；之後由使用者簽名安裝。建置成功只代表工程可產生執行檔，不能證明真機呼叫權限、程序重啟或定位效果。SDK 27.2 不等於裝置系統 27.0.1 或 27.2.1。

## 維護者說明

wloc 維護者將部分新系統的重開機效果歸因於定位記憶體快取，並記錄 MITM 相容性問題。這些是外部專案對其環境的觀察，沒有在本研究裝置上重現，不可代替本機程序或快取證據。來源見 [來源表](sources.md)。

## 推論與未知

成功回報讓系統定位狀態成為值得研究的方向，但尚缺不呼叫入口的相同失效狀態對照、程序重啟證據及快取變化證據。控制 App 與配件狀態也未被完全排除。只有呼叫回傳 YES 不能證明清快取；回傳 NO、例外、無回應也不能單獨證明權限拒絕。
