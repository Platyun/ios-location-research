## 5. 排版要求

- HTML 是完整閱讀版，Markdown 是可直接在 GitHub 讀的同內容原稿；不要只把 Markdown 放進 pre 區塊。
- 以資訊層級、段落、留白、字級、表格與來源連結改善閱讀，不加宣傳標語、虛構分數、裝飾性圖表或沒有作用的按鈕。
- 桌機與手機都能讀；以 390px 視窗檢查，不要整頁水平溢出。寬表格可在各自容器捲動，重點資訊不能被裁掉。
- 設定繁體中文語言、語意化標題、可點目錄、可辨識連結及鍵盤焦點。列印樣式要能讀，但不用另外產 PDF。
- 兩種格式必須對齊所有主張、缺陷 ID、嚴重程度、來源及修正狀態。可用 repo 外暫存轉換工具，避免在純研究 repo 放入程式；不要依賴前一個環境的暫存腳本一定存在。
- HTML 離線開啟即可閱讀，不依賴外部 JS、字型或服務。README 頂部保留兩份報告的 HTML／Markdown 入口。
- GitHub 的 HTML 檔案頁可能顯示原始碼，README 要清楚說明下載後用瀏覽器開啟；不要宣稱已部署網站或 GitHub 能直接渲染這些檔案。
- 若保留 HTML 的 source-sha256 metadata，內容改動後要更新，不能留下不匹配的雜湊。
