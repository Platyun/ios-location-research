## 操作目標已有成功案例

最初問題是失效後必須重開整機，才能讓既有定位工具再次套用位置。最新使用者回報為 iPhone 16 Pro、iOS 27.2.1，實測成功且沒有重開整機。因此，在這次回報的環境與條件下，「免整機重開重新套用位置」已達成。

同一台手機先在 iOS 27.0.1 實測通過：匯出紀錄有方法存在及呼叫回傳 YES，之後使用者回報重新套用成功。使用者隨後把系統更新到 iOS 27.2.1 再複測，仍然成功。兩筆是同一裝置在系統更新前後的先後測試，說明做法在更新後仍可重現；但它們不是兩個獨立樣本，不能計算成功率。

## 效果與機制分開判斷

| 問題 | 目前判斷 |
| --- | --- |
| 不重開整機能否重新套用？ | 有成功案例；最新回報明確確認未重開。 |
| 是否與研究中的系統入口有關？ | 先前紀錄在呼叫後成功，支持繼續使用此方向；未有同狀態的不呼叫對照，因果強度有限。最新回報沒有附逐步紀錄。 |
| locationd 是否真的退出或重新啟動？ | 未證實；沒有程序識別碼變化或系統日誌。 |
| 基地台快取是否被清除？ | 未證實；未觀察快取內容或定位資料庫變化。 |
| 是否能保證所有版本及配件都成功？ | 不能，現有證據限於已回報環境。 |
| 是否一定存在固定 20 km／30 秒限制？ | 無證據支持其為系統固定門檻；早期只是觀察值。 |
| 配置是否單獨解決問題？ | 未證實。曾在配置與重開機合用後成功，但兩者影響未隔離。 |

不以成功維持多久作為本次成敗條件，這是使用者對研究目標的明確界定。此項界定不等於已完成長期穩定性測試。

## 對既有假設的結論

基地台暫存仍是根因假設，尚未與系統定位程序記憶體、磁碟快取、其他定位來源、控制 App 或配件狀態區分。現有結果不足以認定任何一者是唯一原因。

網路阻斷與定位狀態重設是不同研究問題。現有紀錄沒有證明增加封鎖規則能取得系統程序控制能力，也沒有證明阻擋更新等於清除既有狀態。因此，不再把反覆改 DNS、擴大封鎖或購買配件當成本案已證實的下一步。

## 可引用的結論

「同一台 iPhone 16 Pro 在 iOS 27.0.1 實測通過（探測入口回傳 YES 後重新套用成功），更新到 iOS 27.2.1 後複測仍成功，且沒有重開整機。本研究支持免整機重開的操作可行性；尚未證實定位服務重啟、基地台快取清除或所有環境均適用。」
